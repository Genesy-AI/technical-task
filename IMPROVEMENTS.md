# Possible Improvements to the Codebase

* The UX might be better if there was an option to keep the import dialog open after importing a csv file
* It seems like the API endpoints invoke workflows by calling client.workflow.execute instead of client.workflow.start. This means that the request waits on the workflow to complete which seems to void the point of using a workflow to run the job in the background. A better solution would be to run the workflow in the background and have it update its progress and end status either by returning the job ID to the API caller so they can poll for its status later or (more complex) allowing the client to connect via a websocket and having the workflow write its progress and statuses to a temporary storage (e.g. a Redis queue) whose values can then be sent directly to the client
* The validation of the leads imported in the csv is very simplistic and just checks for the types of the fields. Using a validation library could make this more robust and easy to add to
* When adding fields to the lead model it was necessary to add the values in quite a few places because the objects were manually constructed in a lot of places. Perhaps it would be possible to derive more things (e.g. the colums in the frontend table, the expected csv columns etc) from the model so that it would only be necessary to change a few places when adding new fields.
